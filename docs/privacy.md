# Приватность: что фильтр делает и чего не делает

Две разные обещания, и их легко перепутать.

## 1. Наружу ничего не уходит

Сетевых вызовов в рантайме нет: ни телеметрии, ни загрузки моделей «на лету»,
ни обращений к API. HTTP-сервер слушает `127.0.0.1` и проверяет заголовок
`Host`, чтобы страница в браузере не могла через DNS-rebinding попросить
приложение открыть произвольный файл. Эндпоинты открытия принимают `id`
записи индекса, а не путь.

## 2. Часть путей вообще не попадает в индекс

`core/privacy.py` отбрасывает файлы **до того, как их прочитают**:

| Категория | Примеры |
|---|---|
| Ключи и пароли | `.ssh`, `id_rsa*`, `*.kdbx`, `*.pfx`, `wallet.dat` |
| Менеджеры паролей | `1password`, `bitwarden`, `keepass`, `.password-store` |
| Профили браузеров | `AppData/.../Chrome/User Data`, `.../Edge/User Data`, Firefox profiles |
| Облачные ключи | `.aws`, `.azure`, `.kube`, `.gnupg` |
| Секреты в проектах | `*.env`, `*password*`, `*credential*`, `*secret*` |

Исходный код исключён из широких масок по имени: Blender поставляет
`secrets.py`, и индексировать модуль стандартной библиотеки — не инцидент.
Расширения и фрагменты путей при этом продолжают работать.

Фильтр включён по умолчанию. Количество отброшенного печатается в выводе
`index`, показывается в интерфейсе и учитывается в `doctor`.

## Что делать с тем, что уже попало в индекс

```bash
python -m core.cli privacy          # список и причина по каждому файлу
python -m core.cli privacy purge    # убрать из индекса
```

`purge` удаляет записи из базы: файлы на диске остаются, и повторная
индексация с `--allow-sensitive` вернёт их обратно. На машине разработчика
фильтр нашёл два файла «Пароль на архив» — они попали в индекс до того, как
фильтр появился.

## Чего фильтр не делает

- **Не шифрует индекс.** Отфильтрованные пути не индексируются, всё остальное
  лежит в обычном SQLite: текст документов и OCR-текст со всего экрана, включая
  переписку, медицину и рабочие документы. SQLCipher — открытая задача.
- **Не останавливает OCR.** Пауза распознавания (глобальная и по активному
  окну) не реализована: скриншот попадает в индекс при следующем проходе.
- **Не знает про содержимое.** Файл `notes.txt` с паролем внутри пройдёт:
  решение принимается по пути, а не по тексту.
- **Не блокирует приложения.** Чёрного списка окон нет — это часть той же
  нереализованной паузы.

Обещать «приватность» на основании одного фильтра путей было бы обманом.
Фильтр снижает вероятность худшего, но не заменяет шифрование.
