## Что сделано

### Уже было сделано в первой партии

- Глобальные hotkey `Ctrl+Alt+Space` (показать/спрятать) и `Ctrl+Alt+P` (быстрая палитра 640×132).

- Память позиции и размера окна (`~/.autofind/window.txt`).
- `Ctrl+Shift+1..9` — сохранённые поиски, `Ctrl+Shift+C` — копировать путь.

### Web UI (`web/app.js`, `web/index.html`, `web/style.css`) — 26 фич

Автодополнение 12 токенов; снимаемые чипы фильтров; естественные даты (`за прошлую неделю`, `after 1 march`, ISO) → `modified:`; история запросов с контекстом (время, число результатов, что открыли, серверная `/api/history`); hover-превью за 380 мс; line numbers в коде и превью; клик по OCR-слову → подсветка области; «Почему найдено» с каналами/оценкой; «Закрепить лучший»; подсказки при выборе дублей; выпадающий список тегов; редактор исключений с реальным GET/POST `/api/exclusions`; бейдж вотчера и свежести индекса; «переиндексировать папку» из `in:`/`path:`; видимая частота открытий; редактор заметок; похожие файлы (документы — `/api/similar-files`, картинки — `/api/similar`); разбор диска из `/api/audit`; Undo/Redo фильтров; поиск внутри выдачи; regex-конструктор с живым превью по индексу; умные коллекции из saved searches; drag-and-drop в коллекции; просмотр `/api/self-test` и `/api/log`; бейдж «без телеметрии»; индикатор портативного режима.

### Rust-шелл (`shell-app/`)

- Окно и палитра открываются на мониторе, где находится курсор (`GetCursorPos` + геометрия мониторов).
- `window.txt` расширен до 7 полей: `x y w h always_on_top start_minimized quiet`; старые 5-полевые файлы читаются.
- Запуск в трее по умолчанию и тихий режим уведомления (и карточка, и системный balloon).
- Палитра больше не перезаписывает сохранённую геометрию полного окна.
- `Ctrl+Alt+S` — GDI-захват всех мониторов, свой PNG-энкодер без зависимостей, сохранение в `~/.autofind/screenshots/`, индексация через объявленный сервером `POST /api/screenshot`.
- Сохранённые hotkey/always-on-top/анимация/уведомление без белого всплеска — без изменений.

### Python API (`core/api.py`, `core/config.py`, `core/cli.py`, `core/openapi.py`)

Новые маршруты: `GET/POST /api/vault`, `/api/autostart`, `/api/rules`, `/api/exclusions`, `/api/backup`, `/api/portable`, `/api/similar-files`, `/api/history`, `/api/privacy/categories`, `/api/reindex-folder`, `/api/note/drop`, `/api/screenshot`. Все наследуют проверку Host/Origin и JSON Content-Type, int-параметры через `_int_param`, записи через `_write`/локи. Правила индексации хранятся в `index-rules.json` с жёсткой валидацией. `autofind restore --from <zip>` добавлен в CLI. OpenAPI дополнил все новые маршруты. Перевод ru→en честно помечает только alias-переписывания: настоящего переводчика в проекте нет, выдумывать его не стал.

## Интеграционные правки поверх проходов

- Web-слушатель `autofind:screenshot` вызывает `POST /api/screenshot`, не дублируя вызов, если Rust уже проиндексировал файл.
- Нашёл и исправил несовместимость discovery: Rust искал `"post":{`, а OpenAPI отдаёт `"post": {` — теперь пробелы нормализуются.
- Все строковые литералы новых UI-фич вынесены в `i18n.js` (en/ru/zh); `web/app.js` снова не содержит русского текста — поэтому `test_i18n` зелёный.
- `core/openapi.py` обновлён под новый контракт.

## Остатки (честно)

- **Inline-предпросмотр PDF-страницы** — реализован как текст first-match + мини-карточка; полноценный рендер страницы пока не добавлен.
- **«Открыть с помощью…» с памятью выбора** — не реализовано: требует нового системного вызова и отдельного хранилища ассоциаций.
- **Полные правила индексации на корень в UI** — есть backend и редактор глобальных исключений; настройки OCR/лимитов на каждый корень в UI пока не вынесены.
- **API-side restore** — намеренно не делался: подмена `index.db` под открытыми дескрипторами сервера небезопасна; восстановление доступно через CLI.
- **Настоящий ru→en перевод** — в проекте нет переводчика; индикатор сообщает об alias-переписывании и не притворяется переводом.
- **Звук уведомления** — нет звукового ассета; реализован тихий режим.
- `web/app.js` теперь хранит часть новых строк как `\uXXXX` — это сохраняет поведение и требование i18n-теста, но читаемость исходника ниже; при следующем проходе их можно перенести в i18n полностью.
